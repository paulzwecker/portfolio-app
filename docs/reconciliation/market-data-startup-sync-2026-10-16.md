# Milestone 10.0 — Startup Market Data Synchronization

Checked against the local canonical PostgreSQL database on 2026-10-16. Machine-readable counts and run details are in [the JSON report](market-data-startup-sync-2026-10-16.json).

## Diagnosis

The data existed, but two separate issues hid its usefulness. First, the development process inherited `HTTP(S)_PROXY=http://127.0.0.1:9`, an unavailable loopback proxy. Yahoo requests failed with connection refused. A direct request to the exact Yahoo chart hosts succeeded. Second, market measures in Company and Universe responses came from imported `PriceRegimeSnapshot` records only. Those cached snapshots covered 71 of 83 active exact company listings, while clean canonical daily history already had at least 252 sessions for all 83. The missing measures were therefore a query-layer dependency on incomplete legacy snapshots, not absent price history.

Before the bounded refresh, all 83 active company listings had stale current quotes from 2026-10-09. The legacy snapshot covered 21/22 Portfolio listings and 50/61 Watchlist listings. Nine dated EUR currency pairs existed, but their latest observations were 6–10 days old. Ten Watchlist companies still had no exact listing identity. The initial live frontend probe also exposed an exchange-calendar edge case: three Australian quotes were observed before the cutoff but had a market-session date one day ahead of the UTC date; the negative computed age made the strict frontend contract reject the complete Universe market response. Current quotes in this case now use their actual observation date for freshness age, while retaining the exchange session date for historical filtering and display.

Market ingestion writes append-only exact-listing price facts and dated FX. Portfolio overview values the latest accepted holdings snapshot using those observations at its requested valuation and knowledge cutoff. Current native returns use the accepted model revision against the same model listing's eligible market quote; the original accepted reference price and outputs stay in model history. Ranks remain explicit immutable runs and are not regenerated by ingestion. Execution Pace also consumes the exact-listing quote, but its legacy regime input is specifically the stored `PriceRegimeSnapshot` label and freshness. This milestone does not infer that broader legacy label from trend metrics, so stale/missing legacy regime evidence can still leave Execution Pace at `REVIEW`.

## Changes and live result

The local development launcher now starts a dedicated market-data worker. It waits for PostgreSQL and current Alembic heads, checks exact active/held listing coverage and freshness, and invokes the existing Yahoo `MARKET_DATA` and `FX` ingestion path only when needed. A PostgreSQL advisory lock serializes competing starts. Existing bounded backfill and recent correction overlap remain owned by the ingestion worker. A narrow process-local `NO_PROXY` addition applies only when the known loopback port-9 proxy is detected; all other proxy configuration is preserved.

The live refresh completed in 6.22 seconds. It fetched 84 mapped active/held listing identities, received 5,451 price rows and inserted 544. There were no Yahoo price fetch failures or normalization rejections. FX completed for all nine relevant EUR pairs and inserted 69 observations. Market and corporate-action runs remain `PARTIAL`: ten Watchlist companies have unresolved listing identities, and 29 returned corporate-action observations remain unverified. No price, currency, listing, holdings, target, model, score, rank or execution history was fabricated or rewritten.

The API now computes price-only analytics from clean split-adjusted daily closes, independent of legacy regime snapshots. For the active company listings, all 22 Portfolio listings and all 61 mapped Watchlist listings now have fresh quotes and 252-session analytics: 50DMA, 200DMA, 20-day annualized volatility and 52-week drawdown. The Company API returned 90 recent bars for the live ADYEN check. The 52-week high and drawdown stay null until the full 252-session window is available; all return measures explicitly exclude dividends.

The Company, Universe and Portfolio views poll current market data and the refresh-status endpoint every 30 seconds. They show observation dates, update state and partial/unavailable states. Existing valid historical closes remain visible if a quote is stale or a later refresh fails. The worker's immediate replay check skipped in 0.84 seconds because coverage was current, creating no duplicate observations.

The live Portfolio overview now values the accepted snapshot at EUR 57,825.39 across 22 positions including the standalone security, with no price or FX gaps. Its holdings confirmation is 11 days old and remains marked `STALE`; current prices do not refresh quantities. The market summary now passes the frontend contract, and a read-only live browser check displayed the TSM ordinary share and ADR separately at desktop and mobile widths.

## Remaining limits

Ten Watchlist companies still need authoritative exact listing identities. Yahoo dividend and split observations remain unverified; the interface therefore presents split-adjusted price returns and does not label them total returns. The overall refresh state correctly stays `PARTIAL` while those mapping and action-quality issues remain. No operations dashboard existed for a manual refresh button, so the existing CLI worker and ingestion commands remain the manual operational path.
